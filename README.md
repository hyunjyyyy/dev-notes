# dev-notes

이 레포지토리는 **결과보다 사고 과정**을 기록하기 위한 개발/실무 노트입니다.  
인턴십, 프로젝트, 실무 경험을 하며  
“무엇을 만들었는가”보다  
**“어떤 문제를 어떻게 인식했고, 왜 그렇게 판단했는가”**를 남기는 것을 목표로 합니다.

---

## 📁 Repository Structure

이 레포지토리는 크게 두 종류의 기록을 포함합니다.

- `intern_<company>/` : 인턴십 및 실무 경험 기록
- `project_<project-name>/` : 개인/팀 프로젝트 기록

두 유형 모두 **동일한 사고 구조**를 사용합니다.  
(인턴과 프로젝트의 파일 형식은 같으며, 내용의 성격만 다릅니다)

---

## 🧠 Thinking Framework (공통 구조)

모든 폴더는 아래 5단계 사고 흐름을 따릅니다.

```
01_context.md
02_problem-observations.md
03_decision-log.md
04_tradeoffs.md
05_learnings.md
```

---

## 📄 File Guide

### 01_context.md
- 이 일을 하게 된 배경
- 나의 역할과 책임
- 주어진 제약 조건 (시간, 기술, 조직, 정책 등)

### 02_problem-observations.md
- 처음엔 명확하지 않았던 문제들
- “이상하다”고 느꼈던 지점
- 사용자의 불편, 시스템의 한계, 조직적 마찰

### 03_decision-log.md
- 실제로 선택한 해결 방향
- 그 선택을 하게 된 이유
- 참고했던 자료, 가설, 논리

### 04_tradeoffs.md
- 고민했던 다른 선택지들
- 왜 선택하지 않았는지
- 선택으로 인해 포기한 것들

### 05_learnings.md
- 결과와 상관없이 얻은 배움
- 다음엔 다르게 할 점
- 이 경험이 나의 기준에 어떤 영향을 줬는지

---

## ✍️ Writing Principles

- 결과가 없어도 기록한다
- 완벽한 정답보다 **판단 근거**를 남긴다
- “잘했다”보다 “왜 이렇게 했는지”를 설명한다
- 미래의 내가 다시 읽었을 때 이해될 정도로만 쓴다

---

## 🎯 Why This Repo Exists

이 레포는 포트폴리오가 아니라  
**사고 기록 저장소**에 가깝습니다.

면접에서 이런 질문에 답하기 위해 존재합니다.

- “이 문제를 처음 봤을 때 무슨 생각을 했나요?”
- “왜 그 방법을 선택했어요?”
- “다시 한다면 어떻게 바꿀 건가요?”
