# 01_context.md

## 1. 기업 및 프로젝트 배경

### 1.1 근무 기업

* **Mand.ro**: 3D 프린팅 기술을 활용하여 저비용 고성능 로봇 의수 및 기계 의수를 제작하는 스타트업

### 1.2 근무 형태 및 기간

* **산학협력 단기 인턴**: 약 1개월간 소프트웨어 엔지니어로 근무하며 두 가지 주요 플랫폼의 제어 솔루션을 개발함.

<br>

## 2. 개발 목표 및 역할 (Key Deliverables)

### 2.1 Windows 기반 앱: MandroController

* **성격**: 제품 시연 및 연구용 대시보드 애플리케이션
* **주요 기능**:
    * 기존 Third-party 프로그램(ComportMaster)의 시리얼 통신 기능 이식
    * 자체 기능 구현
        - 실시간 P/C/T(Position, Current, Temperature) 데이터 시각화(Graph View)
        - 매크로 실행
        - 로그 필터링 시스템
* **기술 스택**: Python 3.10+, PyQt6, PyQtGraph, PySerial.

### 2.2 Android 기반 앱: MandroController_Android

* **성격**: 실제 의수 사용자가 일상에서 간편하게 조작할 수 있는 모바일 전용 애플리케이션
* **주요 기능**:
    * **무선 제어**: 블루투스 통신을 통한 기기 연결 및 기기 조작 기능 구현
    * **UX 최적화**: 매크로 추가/편집/삭제 기능을 통해 사용자 맞춤형 동작 설정을 지원, 진동 피드백을 통해 조작 편의성을 높임
    * 언어 지원: 한국어와 영어 모두 지원 가능하게 하여 앱 사용성을 높임
* **기술 스택**: Kotlin, Jetpack Compose, Bluetooth API, Vibrator API

<br>

## 3. 이상과 현실 (Expectation vs. Reality)

### 3.1 기대 (Expectation)

* 시니어 개발자의 코드 리뷰와 기술적 가이드라인이 존재하는 환경
* 정교한 API 명세서와 구체화된 기획 문서(PRD)를 바탕으로 한 구현 중심의 업무

### 3.2 현실 (Reality)

* **업무 방식 (1인 개발)**: 사내 유일한 소프트웨어 엔지니어로서, 설계부터 구현, 테스트, 배포(EXE 파일화)까지 전 과정을 독자적으로 수행해야 함.
* **요구사항 전달**: 명확한 기획서 대신 하드웨어 엔지니어와의 소통 및 대표님의 비전, 실제 하드웨어의 동작 분석을 통해 요구사항을 직접 정의하고 구체화.
* **프로세스 성숙도**: 정해진 개발 프레임워크나 아키텍처가 부재한 상태였기에, 유지보수 안정화를 위해 스스로 **MVC 패턴**을 도입하고 **통신 스레드 분리** 등의 구조적 결단을 내려야 했음.

<br>

## 4. 제약 조건 및 도전 과제 (Constraints)

* **기술적 제약**: 윈도우 OS 태블릿 및 모바일 기기의 저사양 환경에서도 끊김 없는 실시간 데이터 처리가 가능하도록 앱 경량화가 요구됨.
* **도메인 학습**: 생소한 하드웨어 통신 프로토콜(바이너리 데이터 파싱 등)을 단기간에 분석하여 소프트웨어 로직으로 변환해야 했음.
* **시간적 압박**: 1개월이라는 짧은 기간 내에 Windows와 Android라는 두 개의 서로 다른 플랫폼 결과물을 모두 완성해야 했음. 특히 Windows 앱은 1주일이라는 시간 내에 CES 2026 제품 시연 때 사용되어야 했으므로 안정성과 완성도 모두 단기간에 이뤄내야 했음.
