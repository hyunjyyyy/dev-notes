# Project Notes — CleanBook

이 폴더는

검색 결과의 피로도를 줄이기 위해 직접 기획하고 출시한 크롬 확장 프로그램

**'CleanBook'을 개발하며 겪은 시행착오와 의사결정**을 기록하기 위한 공간이다.

이 기록의 목적은 단순한 기능 설명이 아니라

**사용자로서 느낀 페인 포인트(Pain Point)를 어떻게 기술적으로 해결하고 제품화했는가**에 대한 답을 찾는 과정이다.

## 📂 기록 구성

### 01_context.md

* 프로젝트 기획 동기: 왜 '서점 검색' 필터가 필요했는가?
* 사용 기술 스택 (Manifest V3, Vanilla JS 등)
* 개발 전 가졌던 가정과 실제 개발 환경의 차이

### 02_problem-observations.md

* 동적 웹사이트(SPA/무선 스크롤)에서 필터가 뚫리는 문제 관찰
* 각 온라인 서점(교보, 알라딘, Yes24)마다 제각각인 DOM 구조 분석

### 03_decision-log.md

* MutationObserver를 활용한 실시간 DOM 감지 결정
* Bottom-Up 방식의 요소 탐색 로직 설계 (Yes24 레이아웃 대응)
* 사용자 편의를 위한 백업/복구 기능 추가

### 04_tradeoffs.md

* 필터링 성능과 웹페이지 로딩 속도 사이의 균형
* Manifest V3 보안 규정을 준수하기 위해 포기하거나 우회한 기능들
* 유지보수 효율을 위한 사이트별 CONFIG 분리 전략

### 05_learnings.md

* 1인 개발자로서 '기획-개발-배포-유지보수' 전체 사이클을 경험하며 배운 점
* 사용자의 피드백(UI 깨짐 등)을 기술적으로 대응하며 얻은 노하우
* '완성'보다 '업데이트'가 중요한 이유


## ✍️ 기록 원칙

* **"불편함"에서 시작된 기술적 호기심을 잃지 않는다**
* 왜 이 기능이 사용자(나 포함)에게 필요했는지 본질을 기록한다
* 코드 한 줄보다 그 코드를 짜게 만든 '판단 근거'를 우선한다
* 다시 보았을 때, "내 문제를 내가 직접 해결한 성취감"이 떠오르도록 쓴다
