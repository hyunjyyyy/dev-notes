## 1. 실시간 감지: MutationObserver 도입

* **결정**: 상시 DOM 변화를 감시하는 `MutationObserver` API 채택.
* **판단 이유**: 무한 스크롤 및 SPA(Single Page Application) 환경에서는 페이지 로드 시 단 한 번 실행되는 `DOMContentLoaded` 방식만으로는 추가되는 도서를 감지할 수 없음. 사용자에게 끊김 없는 필터링 경험을 제공하기 위해서 도입

## 2. 서점 사이트별 데이터 추출 및 레이아웃 대응

### 2.1 교보문고: 중간점(·) 기반 텍스트 파싱 전략

* **결정**: 특정 클래스 타겟팅 대신 부모 클래스 내 전체 텍스트 스캔 후 중간점 기호 기반 매칭 방식 선택
* **판단 이유**: 출판사 정보가 별도 선택자로 분리되지 않은 교보문고의 비정형적 구조에 대응하기 위해서. 신작, 베스트셀러, 검색창 등 사이트 전반에서 공통으로 발견되는 `저자 · 출판사 · 날짜` 규칙을 역이용하는 것이 가장 확실한 방법이었음.

### 2.2 알라딘: URL 식별자 기반 정밀 타겟팅

* **결정**: `a[href*="PublisherSearch"]` 선택자 활용.
* **판단 이유**: 복잡한 클래스명에 의존하기보다, 출판사 검색이라는 명확한 목적을 가진 URL 파라미터를 추적하는 것이 개발 속도와 정확도 면에서 압도적으로 유리했음.

### 2.3 Yes24: Bottom-Up(closest) 로직

* **결정**: `tr` 태그에 `transform: scale(1)`을 주어 새로운 쌓임 맥락(Stacking Context)을 강제 생성하고, `target.closest('tr')`로 부모를 역추적하는 방식 도입
* **판단 이유**: Yes24의 테이블 구조에서는 기존의 Top-Down 방식이나 일반적인 `relative` 포지셔닝으로는 차단하는 UI가 만들어 지지 않거나, 기존 사이트와는 다르게 깨지는 현상 발생
* **AI Collaboration**: 이 문제는 내가 갖고 있는 지식만으로 해결이 어려워 AI에게 다른 방식이 있나고 물었고, 그 과정에서 `transform: scale(1)`을 적용하게 됨.

## 3. 정밀도 개선 (v1.4.2)

* **결정**: 제목/내용이 포함된 광범위한 클래스를 감시 범위에서 전면 배제하고, 저자/출판사 전용 클래스(`.info_auth`, `.info_pub` 등)만 `querySelectorAll`로 전수 조사함.
* **판단 이유**: 'Gemini' 오차단 사례를 통해 필터링 구역을 넓게 잡는 것이 제품의 본질을 훼손할 수 있음을 체감함. 오차단은 사용자에게 꼭 필요한 정보까지 뺏는 것이기에, 필터링 범위가 좁아지더라도 **'정확도'**를 최우선 가치로 설정

## 4. 백업 시스템: JSON 파일 기반 Export/Import

* **결정**: 서버 연동 없이 브라우저 내에서 완결되는 데이터 백업 및 복구 기능 구현
* **판단 이유**: 1인 개발 프로젝트로서 서버 유지 비용을 없애 프로젝트의 지속 가능성을 높이기 위한 선택
