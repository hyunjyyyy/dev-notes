# 01_context.md

## 1. 프로젝트 배경 및 동기
* **발단**: 트위터(X) 내 '독서계'를 중심으로 특정 출판사의 도서들이 검색 결과를 도배한다는 실시간 불만을 포착함.
* **문제 의식**: 사용자가 원치 않는 정보를 스스로 걸러낼 수 있는 '선택권'이 서점 플랫폼에 부재하며, 이로 인해 실제 도서 검색 경험이 크게 저해되고 있었음.
* **해결의 확신**: 과거 해커톤에서 크롬 확장 프로그램을 개발했던 경험을 바탕으로, 문제를 보자마자 확장 프로그램을 통한 해결 직감이 왔음. 특히 오랜 기간 운영된 서점 사이트들은 DOM 구조가 명확히 정의되어 있을 것이라 판단했고, 이를 역이용하면 필터링 구현이 충분히 가능할 것이라 확신함.
* **목표**: 사용자들의 불만이 최고조에 달한 시점에 맞추어, 아이디어 발상 후 3일(72시간) 이내에 MVP 개발 및 배포 완료.

## 2. 전략적 판단
* **타임라인 설정**: 이슈가 트위터에서 널리 퍼지고 있을 때, 그 흐름이 사그라들기 전 개발과 홍보를 완료해야 초기 사용자를 확보하기 유리할 것이라 판단하여 3일이라는 짧은 기한을 설정함.
* **핵심 사용자 가치**: 'MVP에 충실한 자율성 보장'을 최우선으로 함. 단순히 가리는 것을 넘어 오차단(False Positive)을 최소화하는 것에 집중함. (예: 저자 'Gemini'는 차단하되, 제목에 'Gemini'가 들어간 실용서는 노출하는 정밀함 지향)

## 3. 기술 스택
* **핵심 기술**: Vanilla JS, Chrome Extension API (Manifest V3).
* **선택 이유**: 라이브러리 의존성을 최소화하여 브라우저 성능에 영향을 주지 않는 가벼운 확장 프로그램을 지향하며, 빠른 배포를 위해 순수 자바스크립트를 채택함.
