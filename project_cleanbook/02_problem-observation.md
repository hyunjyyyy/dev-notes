# 02_problem-observation.md

## 1. [Phase 1] 초기 개발 및 사이트별 특이점
* **무한 스크롤의 벽**: 정적 스캔 방식으로는 스크롤 시 추가되는 도서를 잡지 못하는 현상 관찰
* **교보문고 (텍스트 파칭)**: 출판사 클래스가 따로 없고 중간점(`·`) 사이에 텍스트가 섞여 있어 일반적인 선택자로 접근 불가
* **알라딘 (복잡한 클래스)**: 클래스명이 규칙성이 없어 DOM 구조만으로 타겟팅하기 어려움

## 2. [Phase 2~3] 확장과 정밀도 이슈
* **Yes24 (레이아웃 붕괴)**: 테이블(`tr`) 구조 특성상 가림막을 씌우면 UI가 뭉개지는 현상 확인
* **알라딘 저자 필터링**: `querySelector`가 첫 번째 요소만 검사하여 저자명이 뒤에 오는 경우 필터링 누락 발생

## 3. [Phase 4] 오차단(False Positive)
* **범위 설정 오류**: 'Gemini' 키워드 차단 시 'Geminiani' 같은 단어가 포함된 도서까지 모두 가려지는 치명적 버그 발견

* **Q. 교보문고의 '중간점' 구조를 처음 발견했을 때 어떤 기분이었고, 어떻게 파싱할 아이디어를 얻었나요?**
    * 솔직히 말하면 진짜 짜증났음. 사실 출판사 이름 누르면 출판사로 이동하는 UX는 기본적으로 가지고 있을거라고 생각했고, 그렇기 때문에 거의 필수적으로 출판사 클래스가 있을 거라고 생각했음.
    * 교보문고 사이트 내에서 신작/베스트셀러/검색 전체적으로 `저자 · 출판사 · 날짜` 구조였기 때문에 중간점을 기준으로 찾으면 되겠다고 생각했음.
* **Q. Yes24의 테이블 구조 때문에 UI가 다 깨졌을 때, 가장 당황스러웠던 점은?**
    * 혹시 아예 다른 사이트 블락 구조도 다 바꿔야 할까봐 당황스러웠음. 이렇게 되면 다시 개발 첫날로 돌아가서 버그 테스팅 다시 해야하니까!
* **Q. 'Gemini' 오차단 버그를 발견했을 때, "아차" 싶었던 지점은 어디였나요?**
    * 오히려 필터링 안될까봐 넓게 필터링 구역을 잡은 것이 기본 MVP를 침해하는 일이 된 것.
    * 나름 꼼꼼히 미리 테스트하고 배포한다고 한건데 놓친 부분이 있다는 것.
