# 01_context.md

## 1. 프로젝트 배경 및 동기
* **발단**: 보육교사 일자리를 찾는 친구가 서울 어린이집 채용공고를 보려면 서울시육아종합지원센터 게시판과 위탁재단(푸르니, 삼성, 한솔, 한국아동보육복지협회 등) 채용 사이트를 매번 따로 들어가 봐야 했음.
* **문제 의식**: 공고는 하루에도 수십 건씩 올라오는데 게시판마다 정렬 기준이 다르고, "마감이 언제인지"를 한눈에 비교할 수가 없음. 센터 게시판은 서울 25개 구가 한 곳에 섞여 있어 구 필터도 없음.
* **목표**: 흩어진 공고를 한 화면에 마감순으로 모으고, 구·시설유형·재단으로 거를 수 있게 한다. 지원은 원문에서 하도록 링크만 건다.
* **(직접 채우기)** 처음 이 불편을 들었을 때 "이건 내가 만들 수 있겠다"고 판단한 근거.

## 2. 전략적 판단
* **운영 비용 0을 최우선으로**: 친구 한 명이 쓰는 도구라 수익이 없고, 몇 달 뒤에도 내가 손대지 않아도 돌아가야 함. 그래서 "서버 없음, DB 없음, 유료 서비스 없음, 설치할 패키지 없음"을 처음부터 제약으로 걸었음.
* **갱신 주기는 하루 두 번이면 충분**: 공고는 분 단위로 바뀌지 않음. 출근 전(08:00)과 퇴근 무렵(18:00) 두 번이면 실사용에 지장이 없다고 판단하고, 이 가정 덕분에 실시간 서버 없이 "주기적으로 파일 하나를 다시 만드는" 구조가 가능해짐.
* **첫 커밋에 끝까지 가는 뼈대를 넣기**: 2026-10-13 첫 커밋에 수집기·화면·Actions 워크플로를 한 번에 넣고, 같은 날 출처 4개를 더 붙였음. 출처를 추가하는 일이 가장 자주 생길 일이라고 보고 처음부터 플러그인 구조로 짰음.

## 3. 기술 스택

| 층 | 기술 | 하는 일 |
| --- | --- | --- |
| 수집 | Python 3.12, 표준 라이브러리만 (`urllib`, `re`, `html`, `json`, `pathlib`, `datetime`) | 출처 사이트 HTML을 받아 공고 목록을 `docs/data/jobs.json` 하나로 만든다 |
| 저장 | Git 저장소 (`jobs.json`, `data/detail-cache.json` 커밋) | 공고 데이터와 상세 캐시를 버전 관리로 보관한다 |
| 자동화 | GitHub Actions (`schedule` cron + `workflow_dispatch`) | KST 08:00, 18:00에 수집기를 돌리고 바뀐 파일만 커밋·푸시한다 |
| 화면 | HTML + CSS + Vanilla JS, 빌드 없음 | `jobs.json`을 `fetch`해서 브라우저에서 필터·정렬·렌더링한다 |
| 개인화 | `localStorage` | 필터 상태와 관심 어린이집 목록을 브라우저에 저장한다 |
| 폰트 | Pretendard Variable (jsDelivr CDN, dynamic subset) | 한글 가독성. 유일한 외부 의존 |
| 배포 | GitHub Pages (`main` 브랜치 `/docs`) | 정적 파일을 그대로 HTTPS로 서비스한다 |

* **선택 이유 (한 줄 요약)**: 모든 층이 GitHub 안에서 끝나고, 어떤 계정·비용·설치도 추가로 필요 없음. 각 선택의 상세 근거는 `03_decision-log.md`, 안 쓴 대안은 `04_tradeoffs.md`에 있음.

## 4. 개발 전 가정과 실제의 차이
* **가정**: 출처 사이트는 오래된 JSP 게시판이라 서버가 완성된 HTML을 내려줄 것이고, 그러면 브라우저 자동화 없이 정규식으로 충분할 것이다. → **맞았음.** 다섯 출처 전부 정적 HTML이었고 Playwright 같은 도구는 필요 없었음.
* **가정**: 상세 페이지는 그냥 전부 받으면 된다. → **틀렸음.** 15분에 600건쯤 받으니 센터 사이트가 IP를 20~30분 막았음. 결국 실행당 300건, 1초 간격으로 제한하고 캐시를 두게 됨 (`02`, `03` 참고).
* **가정**: 게시판에 보이는 공고 수가 곧 실제 공고 수다. → **틀렸음.** 어린이집이 같은 공고를 끌어올리려고 매일 새 글로 올려서, 목록의 약 20%가 재게시였음.

## 5. AI와의 협업
* 코드 작성과 디버깅은 Claude Code와 함께 진행했고, 커밋에 공동 작성자로 남겨 두었음. 어떤 출처를 넣을지, 어떤 직종만 남길지, 재게시를 어떻게 처리할지 같은 **제품 판단은 내가 내리고**, 구현과 데이터 검증(이전 커밋과 비교해 중복률 계산 등)은 AI에게 맡기는 식으로 나눴음.
* **(직접 채우기)** 이 분업이 잘 맞았던 지점과 아쉬웠던 지점.
