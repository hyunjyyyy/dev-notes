# 02_problem-observation.md

## 1. [Phase 1] 출처마다 다른 구조, "서울"을 가리는 방법도 제각각
* **센터 게시판 (seoul-ccef)**: 목록을 `limit=5000`으로 한 번에 받을 수 있어 편했지만(약 1,800건, 4MB), 구인 중 여부는 `endYn=N` 파라미터로만 걸러짐. 행마다 `fnGoBoardSl('번호')` 같은 자바스크립트 호출이 유일한 식별자라 이걸 정규식으로 잡아야 했음.
* **푸르니**: 전국 공고가 섞여 있어 제목 앞 `[지역]` 대괄호를 파싱해 서울만 남겨야 했음.
* **삼성복지재단**: 주소 칸이 아예 없음. 연락처가 `02`로 시작하는지로 서울을 판별하고, 구는 센터 게시판에서 그 어린이집 이름으로 지난 공고를 검색해 알아내야 했음.
* **한솔**: 본문이 `recruit.do` iframe 안에 있어 목록 페이지만 봐서는 근무지를 알 수 없음. 상세의 '근무지' 칸을 읽어야 서울 여부가 나옴.
* **한국아동보육복지협회 (kacew)**: 본문이 이미지라 접수기간을 읽을 수 없음. 마감일 없이 게시일 60일 이내 글만 보여주는 걸로 타협.
* **관찰 요약**: "서울 공고만 모은다"는 한 문장이 출처마다 완전히 다른 다섯 가지 구현이 됨. 공통 코드로 묶을 수 없다는 게 분명해져서 출처별 모듈 구조로 감.

## 2. [Phase 2] 상세 페이지를 받다가 IP가 막힘
* **현상**: 재단 정보와 자기소개서 여부를 뽑으려고 센터 게시판 상세 페이지를 전부 받기 시작하자, 15분에 600건쯤에서 사이트가 응답을 끊음. 20~30분 뒤 풀림.
* **1차 대응**: 실행당 600건, 1초 간격으로 제한 → 그래도 막힘 (커밋 `7cc6462` → `ab71f14`).
* **2차 대응**: 실행당 300건으로 더 줄이고, 한 번 받은 상세는 `data/detail-cache.json`에 저장해 다시 받지 않음. 나머지는 다음 실행으로 미룸. 하루 두 번 × 300건이면 신규 공고는 하루 안에 다 채워짐.
* **관찰 요약**: 전체 공고는 2,000건인데 하루에 새로 올라오는 건 수십 건. "처음 본 공고만 상세를 받는다"는 규칙만 있으면 속도 제한이 전혀 문제가 안 됨.

## 3. [Phase 3] 재단별로 보고 싶다는 요청 → 센터 게시판에는 재단 칸이 없음
* **현상**: 친구가 특정 재단(위탁 운영) 어린이집만 모아 보고 싶어 했는데, 센터 게시판에는 운영 재단 필드가 없음.
* **관찰 1**: 재단 채용 사이트를 출처로 따로 붙이면 그 재단은 해결됨 (푸르니·삼성·한솔·협회).
* **관찰 2**: 킨더슐레·한빛처럼 자체 채용 사이트 없이 센터 게시판에만 올리는 재단도 있음. 이건 상세 본문에 적힌 재단 이름을 정규식으로 찾아내는 수밖에 없었음. 이게 Phase 2의 "상세를 전부 받아야 한다"는 요구를 만든 원인.
* **관찰 3**: 재단 사이트 공고와 센터 게시판 공고가 같은 공고인 경우가 있어, 재단별 보기에서는 어린이집 이름과 마감일이 같으면 하나로 보여줘야 했음.

## 4. [Phase 4] "업데이트될 때마다 같은 공고가 또 추가되는 것 같다"
* **현상**: 갱신 뒤 목록을 보면 같은 어린이집, 같은 제목이 여러 개 보임. 처음엔 스크레이퍼가 중복을 만드는 줄 알았음.
* **검증**: 어제 데이터와 오늘 데이터를 id로 비교. 2,050건 중 2,014건이 같은 id로 유지됐고 같은 id나 URL이 두 번 들어간 경우는 0건 → 스크레이퍼 문제가 아님.
* **진짜 원인**: 어린이집이 같은 공고를 끌어올리려고 매일 새 글(새 게시글 번호)로 올리고, 사이트는 이전 글도 전부 "구인 중"으로 남겨 둠. 한 어린이집이 같은 제목으로 9~10번 올라와 있기도 했고, 전체의 약 20%(413건)가 재게시였음. 새로 들어오는 공고의 약 3분의 1도 재게시.
* **관찰 요약**: "같은 공고"의 기준을 우리가 정해야 함. id는 전부 다르니 어린이집·제목·직종 같은 내용 기준으로 묶어야 함.

## 5. [Phase 5] 다른 직종은 안 본다
* **현상**: 조리원, 보조교사, 대체교사, 영양사 공고가 절반 가까이 섞여 있었음. 친구에게는 보육교사 공고만 필요함.
* **관찰**: 직종 필터는 있었지만 매번 눌러야 했고, 실행당 300건인 상세 요청 예산도 안 볼 직종에 쓰이고 있었음. 화면에서 거르는 것보다 수집 단계에서 빼는 게 맞다고 봄.
