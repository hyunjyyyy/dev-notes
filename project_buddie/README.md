## 📂 기록 구성

### 01_context.md

* 프로젝트 동기: 왜 보육교사 공고를 따로 모아야 했는가?
* 사용 기술 스택 (Python 표준 라이브러리, Vanilla JS, GitHub Actions, GitHub Pages)
* 처음부터 정한 제약: 의존성 0, 비용 0, 운영 0

### 02_problem-observation.md

* 출처 사이트마다 제각각인 HTML 구조와 "서울" 판별 문제
* 상세 페이지를 몰아 받으면 IP가 막히는 문제
* 같은 공고가 매일 새 글로 올라와 목록이 부풀어 보이던 문제

### 03_decision-log.md

* 정규식 파싱과 표준 라이브러리만 쓰기로 한 결정
* Git 저장소를 DB로, GitHub Actions를 스케줄러로 쓴 결정
* 출처 플러그인 구조, 상세 캐시, 재게시 중복 제거, 직종 축소

### 04_tradeoffs.md

* 고민했던 다른 선택지(requests/BeautifulSoup, React, Lambda, Netlify 등)와 안 쓴 이유
* 선택 때문에 포기한 것들

### 05_learnings.md

* 결과와 상관없이 얻은 배움
* 다음엔 다르게 할 점

## ✍️ 기록 원칙

* 비슷한 기술을 왜 안 썼는지까지 적는다
