# 📋 Project Notes — YakSok (약속)

이 폴더는 **SMWU AI Hackathon 2025**에서 '포텐셜' 팀이 개발한 **AI 기반 의료 물류 최적화 솔루션 'YakSok'**의 제품 개발 기록이다.

이 기록의 목적은 전체 프로덕트의 방향성을 설계한 **IT PM**으로서의 기획력과, 데이터 무결성 및 API 아키텍처를 직접 구현한 **백엔드 엔지니어**로서의 기술적 문제 해결 과정을 통합적으로 보여주기 위함이다.

## 📂 기록 구성

### 01_context.md

* **Product Vision**: 복잡한 ERP 도입이 어려운 중소 병원을 타겟으로, 'CSV 업로드'만으로 즉시 시각화 대시보드와 AI 리포트를 제공하는 **경량화 SaaS** 기획 동기.
* **ESG Value Proposition**: 과잉 재고를 단순한 비용 손실이 아닌 '탄소 배출량(CO₂)'으로 환산하여 병원의 ESG 경영 지표로 제공하는 비즈니스 모델.
* **System Architecture**: 전체 서비스(React 프론트엔드 - Flask 백엔드 - MySQL - Gemini AI)의 데이터 흐름 설계 및 기술 스택 선정 이유.

### 02_problem-observations.md

* **Domain Pain Point**: 병원 물류 현장에서 가장 치명적인 '유통기한 관리 실패'와 '재고 불일치' 문제 관찰.
* **Data Modeling (Backend)**: 이 문제를 기술적으로 해결하기 위해 `items`, `inventory_batches`, `transactions` 3개의 테이블로 관계형 DB를 모델링하여 '배치(Batch) 단위의 유통기한 추적' 구조 확립.
* **Paper Research**: 해커톤 아이디어를 논문 경진대회로 고도화하며 조사한 의료 폐기물 현황 및 물류 자동화 관련 학술적 한계점 분석.

### 03_decision-log.md

* **Atomic Transaction 설계 (Backend)**: 동시 다발적인 출고 상황에서 데이터 정합성을 보장하기 위해, 출고 로직을 MySQL Stored Procedure(`perform_fifo_shipment`)를 활용한 FIFO(선입선출) 원자적 트랜잭션으로 구현한 기술적 결정.
* **예측 모델 선정 (PM)**: 20시간이라는 해커톤 제약 속에서 복잡한 딥러닝 대신, 최근 90일 트랜잭션 기반의 ADU(일일 평균 소모량)를 계산하여 `days_left`(예상 소진일)를 직관적으로 산출하는 실용적 로직 채택.
* **LLM 리포트 파이프라인**: 백엔드에서 가공한 정량적 통계(폐기율, 재고 회전율)를 Gemini API에 주입하여, 의사결정권자(원장님)를 위한 '스토리텔링형 대책 보고서'로 변환하는 프롬프트 엔지니어링 로직.

### 04_tradeoffs.md

* **개발 속도 vs 데이터 정밀도 (PM)**: 완벽한 실시간 연동 대신 'CSV 배치 업로드' 방식을 택하여 MVP 개발 속도와 중소병원의 접근성을 동시에 확보한 트레이드오프.
* **DB 프로시저 vs 애플리케이션 로직 (Backend)**: 비즈니스 로직(FIFO)의 일부를 DB 계층으로 내려 서버의 부하를 줄이고 무결성을 극대화한 엔지니어링적 선택.
* **기능의 취사선택**: '교환/나눔 생태계 구축'이라는 장기 비전을 위해, 해커톤 단계에서는 무리한 외부 연동보다 '내부 데이터의 시각화 및 알림(긴급 발주 등)'에 프론트엔드 리소스를 집중한 우선순위 관리.

### 05_learnings-&-next-step.md

* **융합형 인재로의 성장**: 전체 UI/UX와 제품 가치를 고민하는 기획자(PM)의 역할을 수행하면서도, 그것을 뒷받침하는 탄탄한 백엔드 시스템(API, DB)을 직접 구축해 낸 풀스택적 경험 회고.
* **데이터 기반 설득**: 개발한 시스템이 어떻게 '폐기율 감소'라는 실질적 비즈니스 가치로 치환되고, 논문이라는 학술적 형태로 신뢰도를 얻게 되었는지에 대한 고찰.
* **Next Step**: 향후 B2B 솔루션 상용화를 위해 필요한 외부 API(WHO, 보건복지부 등) 연동 계획 및 아키텍처 고도화 방안.

## ✍️ 기록 원칙

* **"기술적 완성도는 사용자 경험(UX)과 비즈니스 가치(ESG)를 향할 때 의미가 있다."**
* 기획자로서 왜 이 기능(대시보드, AI 리포트)을 넣었는지 명시하고, 엔지니어로서 그 기저의 데이터 흐름(트랜잭션, FIFO 로직)을 어떻게 짰는지 상세히 기록한다.
* 전체 프로젝트(YakSok)의 큰 그림을 놓치지 않으면서, 내가 주도적으로 책임진 백엔드 영역의 전문성을 확실하게 어필한다.
* 이 기록은 향후 **소프트웨어 엔지니어 실무 역량**과 **IT PM 프로덕트 관리 역량**을 동시에 증명하는 나만의 강력한 무기가 된다.
